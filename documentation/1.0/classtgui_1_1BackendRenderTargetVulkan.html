Detailed Description

Render target implementation that uses Vulkan.

Before the gui can be drawn, either setRenderPass or setDynamicRenderingFormats has to be called to specify where the gui will be rendered to.

bool tgui::BackendRenderTargetVulkan::drawGui ( const std::shared_ptr< RootContainer > & root,
VkCommandBuffer cmdBuffer )

Draws the gui and all of its widgets.

Parameters
rootRoot container that holds all widgets in the gui
cmdBufferCommand buffer to record the draw commands in, which must be inside an active render pass
Returns
True if there weren't any errors, false if something went wrong (e.g. could not create a buffer)

This function should be called once per frame. Textures may still be uploaded to the GPU during this call, which happens by submitting a separate command buffer to the queue. The command buffer must be submitted to the queue that was passed to the renderer in the VulkanContext, because the texture uploads are only synchronized with work that is submitted to that same queue.

Warning
Bound pipeline, vertex buffer, index buffer and descriptor sets will be changed by this function
Viewport and scissor are changed by this function. The scissor will contain the entire target afterwards.

void tgui::BackendRenderTargetVulkan::setDynamicRenderingFormats ( VkFormat colorFormat,
std::uint32_t maxFramesInFlight,
VkFormat depthFormat = VK_FORMAT_UNDEFINED,
VkFormat stencilFormat = VK_FORMAT_UNDEFINED,
VkSampleCountFlagBits samples = VK_SAMPLE_COUNT_1_BIT )

Informs the render target that the gui will be drawn with dynamic rendering (vkCmdBeginRendering).

Parameters
colorFormatFormat of the color attachment
maxFramesInFlightMaximum number of frames that your render loop lets the GPU execute at the same time (e.g. the amount of per-frame fences that you wait on). When drawGui is called, the frame that was drawn maxFramesInFlight frames earlier must have finished executing, otherwise TGUI can overwrite buffers that the GPU is still reading from. A value that is higher than needed only costs a bit of memory.
depthFormatFormat of the depth attachment, or VK_FORMAT_UNDEFINED if there is none
stencilFormatFormat of the stencil attachment, or VK_FORMAT_UNDEFINED if there is none
samplesAmount of samples of the attachments

Exactly one color attachment must be used. sRGB formats are supported, but alpha blending then happens in linear space, so semi-transparent parts can look slightly different than with a UNORM format. Changing maxFramesInFlight waits until the queue is idle, as the resources of all frames are recreated. It thus shouldn't be changed while a command buffer in which the gui was drawn still has to be submitted. Dynamic rendering requires Vulkan 1.3 or the VK_KHR_dynamic_rendering extension, and the dynamicRendering feature has to be enabled on the device.
