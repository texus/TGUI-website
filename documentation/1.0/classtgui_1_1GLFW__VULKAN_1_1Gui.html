Detailed Description

Gui class for GLFW, using Vulkan for rendering and FreeType for fonts.

When using the mainLoop() function, TGUI will create the swapchain and surface internally. Otherwise you must call setRenderPass or setDynamicRenderingFormats once before using the draw function.

void tgui::GLFW_VULKAN::Gui::draw ( VkCommandBuffer cmdBuffer)

Draws all the widgets that were added to the gui.

Parameters
cmdBufferCommand buffer to record the draw commands in, which must be inside an active render pass

This function should be called once per frame. The command buffer has to be submitted to the queue that was passed to the gui. Before calling this function, setRenderPass or setDynamicRenderingFormats must have been called.

Warning
Bound pipeline, vertex buffer, index buffer and descriptor sets will be changed by this function
Viewport and scissor are changed by this function. The scissor will contain the entire window afterwards.

◆ setDynamicRenderingFormats()

void tgui::GLFW_VULKAN::Gui::setDynamicRenderingFormats ( VkFormat colorFormat,
std::uint32_t maxFramesInFlight,
VkFormat depthFormat = VK_FORMAT_UNDEFINED,
VkFormat stencilFormat = VK_FORMAT_UNDEFINED,
VkSampleCountFlagBits samples = VK_SAMPLE_COUNT_1_BIT )

Informs the gui that draw(cmdBuffer) will be called while using dynamic rendering (vkCmdBeginRendering).

Parameters
colorFormatFormat of the color attachment
maxFramesInFlightMaximum number of frames that your render loop lets the GPU execute at the same time (e.g. the amount of per-frame fences that you wait on). When draw(cmdBuffer) is called, the frame that was drawn maxFramesInFlight frames earlier must have finished executing, otherwise TGUI can overwrite buffers that the GPU is still reading from. A value that is higher than needed only costs a bit of memory.
depthFormatFormat of the depth attachment, or VK_FORMAT_UNDEFINED if there is none
stencilFormatFormat of the stencil attachment, or VK_FORMAT_UNDEFINED if there is none
samplesAmount of samples of the attachments

This function doesn't need to be called when using gui.mainLoop(). Dynamic rendering requires Vulkan 1.3 or the VK_KHR_dynamic_rendering extension, and the dynamicRendering feature has to be enabled on the device. Exactly one color attachment must be used. sRGB formats are supported, but alpha blending then happens in linear space, so semi-transparent parts can look slightly different than with a UNORM format. Changing maxFramesInFlight waits until the queue is idle, so it shouldn't be changed while a command buffer in which the gui was drawn still has to be submitted.
